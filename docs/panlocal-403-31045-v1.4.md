# PanLocal V1.4：修复百度个人文件下载 403/31045，并简化操作

## 来自手机实际 TXT 日志的证据

用户实机上传的 PanLocal 诊断记录（2026-10-18 01:29–01:32）已证实：
- `restoreAuthorized=true errno=0`：APP 自动恢复本人账号授权成功。
- `search errno=0 count=1`：已查到目标视频。
- `filemetas errno=0 dlinkPresent=true`：百度返回原始 dlink。
- 多次 `DLCHECK` 均为 `HTTP 403 errorCode=31045`，同时 `userAgentSet=true range0to0=true`。

因此用户并未操作错误，也无需继续调整已经通过的 OAuth、搜索、文件元信息阶段。

## 代码根因和修复

V1.3 `LocalDriveActivity.checkDlink` 对 dlink 发起 GET 时设置了
`User-Agent: pan.baidu.com` 和 `Range: bytes=0-0`，**却没有携带已经取得的个人网盘 OAuth access_token**。

百度开发者中心关于 dlink 返回 403 的答复要求检查 **access_token 和 UA 两个必传条件**：
https://developer.baidu.com/question/detail.html?id=141

另有第三方下载实现使用 `dlink + &access_token=<token>`：
https://cpanbaidu.readthedocs.io/zh-cn/latest/more/downfile/

V1.4：
- 只在 APP 内部执行下载权限测试时，动态追加当前**已经验证的 OAuth access_token** 到百度 PCS dlink，保留 `User-Agent: pan.baidu.com` 与 1 字节 Range 请求。
- 强制百度官方下载 HTTPS 域名白名单，并限制重定向；不向不可信目标携带 OAuth 令牌。
- 不记录完整 dlink、Token、下载 URL 或任何 OAuth 敏感值到 TXT，也不把带 Token 的链接复制到剪贴板。
- 搜索结果上的按钮简化为 **“检查此文件能否下载”**，自动执行 `filemetas -> dlink -> 携带 OAuth 的首字节测试`，不要求用户再点一次验证或自己拼接下载链接。
- 错误诊断记录 `oauthTokenAttached=true` 这一非敏感布尔值、HTTP 状态、`errorCode`，用于判断下一个失败环节。
- 如果用户只是复制原始 dlink 粘贴普通浏览器，可能仍然报 403/31045；复制链接不是此次验证的正确方法。

## 本轮验收口径

编译通过不等于真实下载通过。需安卓实机测试：
1. 安装 V1.4 后打开“我的网盘”，确认可自动登录；无需重新保存 SecretKey、无需重新授权（除非安卓卸载重装导致数据清除）。
2. 搜索“传奇”，点击找到的视频下的 **“检查此文件能否下载”**；无需复制任何 URL。
3. 如果结果 HTTP 206/200 且收到数据首字节：标记**授权下载初步通过**，后续再单独开发完整 2.27 GiB 下载、进度与续传。
4. 如果仍然是 403/31045：保留安全日志，排查文件权限、有效期、设备/IP 限制及 Range 兼容性。不能承诺更改 UA 和 Token 必然突破服务端限制。
5. 成功或失败都通过原 APP 首页的“保存诊断 TXT”导出，分享前检查是否含敏感信息。

**保留原分享解析、密钥与 Token 的本机 Android Keystore 加密保存、服务器 OAuth Bridge 及高级诊断。新加坡服务器未修改。**
