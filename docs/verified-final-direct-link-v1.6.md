# PanLocal V1.6 — 直接进入我的网盘并复制最终下载跳转地址

## 依据与用户反馈

用户手机 V1.4 实测：带已授权 access_token 和 `User-Agent: pan.baidu.com` 的下载测试经过 HTTP 302→206，视频 MP4 首字节实际读取成功。V1.5 手机上已经可以开始将文件流写入手机（截图约 2.9/2270.7 MiB），**但完整下载、断点续传、哈希仍未通过实测**。

用户指出旧首页先呈现“分享信息”“我的网盘 OAuth 测试入口”两大区域，每次还要点进“我的网盘”；希望直接获得**发送要求的请求头后，经 HTTP 302 跳转最终形成的下载 URL**。

## 变更

1. `LocalDriveActivity` 成为 APK 的唯一 MAIN/LAUNCHER，打开图标直接到“我的网盘”，优先显示个人网盘登录状态、文件搜索、下载。
2. 旧 `MainActivity` 不再作为首页启动，但保留 Android SEND 分享入口和历史诊断。可从“高级功能 / 诊断 → 旧版分享链接与完整日志界面”进入，避免删掉原有功能。
3. 文件结果保留两个操作：**下载到手机** 和 **获取最终下载直链（自动验证）**。
4. 选择“获取最终下载直链”后，先调用 filemetas 获取新原始 dlink，然后在内存中附加本人有效 OAuth 令牌、使用 `User-Agent: pan.baidu.com` 和一字节 Range 请求，跟随可信 HTTPS 百度 PCS 主机的 302 跳转。只有最终状态为 200/206 且实际读到文件数据，才显示 **“复制验证后的最终下载直链”**。
5. 复制的是 **最后一次成功读取数据的终点 URL**，不一定是原始 dlink。只在用户主动点击时进入本机剪贴板，不写进诊断日志、GitHub 或服务器，也不自动分享；重新搜索/检测将清除旧地址。
6. 即使复制了最终 URL，也 **不能保证不带请求头的普通浏览器能下载**。它可能短时失效、包含签名或访问令牌，并且需要 User-Agent 或额外服务器认可条件。不是永久、免授权、无时效的公开下载链接。

## 安全

- 完整最终下载 URL **属于敏感临时凭据**，有可能包含 access_token、临时签名或其他授权参数。仅允许明确点击“复制”后暴露到剪贴板。建议在可信设备使用，不要发送到聊天、日志或公开网址。
- 不把真实 SecretKey 固定进 APK；继续使用 Android Keystore 保存开发者密钥及本人 OAuth 授权，支持自动恢复。
- 只跟随允许的百度 PCS HTTPS 域名，不放开跳转到任意外部地址。

## 验收

- 【待手机实测】打开 APP 是否直接显示“我的网盘”而非旧分享首页。
- 【待手机实测】选中文件 → “获取最终下载直链（自动验证）” → 看到成功结果和“复制验证后的最终下载直链”。
- 【待手机实测】复制的最终 URL 是否能在第三方下载器使用；其有效期与所需请求头尚未确认。
- 【历史手机实测】V1.4 的 HTTP 206 MP4 首字节成功；V1.5 已开始接收部分数据。
- 【编译以 CI 为准】GitHub Actions 成功只证明 APK 构建成功，不代表整文件下载已验证。

更新前注意：CI debug APK 可能与旧版签名不一致；必须卸载旧版时，本机 OAuth 密钥、缓存、未导出的诊断日志可能被删除；已保存至外部手机文件夹的下载文件不应因卸载删除，但需用户确认。
