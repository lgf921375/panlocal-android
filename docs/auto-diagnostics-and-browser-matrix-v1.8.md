# PanLocal V1.8 自动诊断与无服务器下载条件对照（2026-10-18）

## 基于用户实机反馈

V1.7 手机截图已确认：
- 已授权下载请求成功，HTTP 206；
- 不带额外 OAuth / Cookie / 百度下载专用 UA 的普通 GET 返回 HTTP 403；
- 不带 OAuth / Cookie 的普通 Range 请求也返回 HTTP 403；
- 因此 V1.7 未能为这份 2270.66 MiB 视频生成能直接分享的匿名浏览器直链。不得把授权下载成功等同于匿名分享直链成功。

## 本轮目标

**无需自己的服务器，也不重新配置已有本机百度授权**，自动记录诊断，并用可重复、脱敏的对照实验定位下载失败的访问条件；不声称能绕过百度服务器的限制。

## V1.8 实现

1. `DiagnosticLog.init()` 随 APP 启动自动启用，无需去旧页面点击「开始诊断」。进程重启自动追加记录，而不是每次清空。日志留在 APP 私有目录，默认最大 2 MiB，超过上限后自动保留最近约 1 MiB（按换行对齐），避免突然停止记录。
2. 直接在「我的网盘 → 高级功能 / 诊断」显示「导出自动诊断 TXT」，调用 Android 原生文档保存界面；无需额外存储权限；不上传任何日志。旧版分享页亦更新为「清空旧日志（可选）」，防止误以为必须每次手动开启。
3. `BrowserDirectLinkProbe` 在授权链路返回 MP4 首字节后，对同一份最终 CDN 地址执行 **四组**有限字节 HTTP 对照：
   - **Chrome 标准 GET**：Chrome UA，不附带 OAuth / Cookie，也不主动发送 Range；
   - **Chrome Range**：同上，`Range: bytes=0-0`；
   - **百度 UA 单变量**：`User-Agent: pan.baidu.com`，不附带 OAuth，`Range: bytes=0-0`；
   - **OAuth 单变量**：Chrome UA，附带已经授权的 OAuth `access_token`，`Range: bytes=0-0`。
4. 仅发送可信 HTTPS 百度 PCS 下载域名请求，最多跟随有限次数的可信重定向，只读取最多 1 字节后即关闭；敏感 URL/令牌仅保留在内存，不进入 TXT 日志或剪贴板。
5. 若标准 Chrome GET 不能取得真实文件数据，**不显示匿名候选链接复制按钮**。可根据四组状态区分「UA 可能是必要条件」「OAuth 可能是必要条件」「单项条件均无效或有其它服务端限制」。
6. 继续保留 V1.6 / V1.7 原本的「下载到手机」「本人网盘授权」「获取最终地址」功能；只在本人已经合法授权的文件上测试。

## 验收口径

- 代码及 APK CI 通过 ≠ Android 真实请求通过。
- 截图中的 V1.7 标准 GET/Range HTTP 403 是**真实失败证据**；V1.8 四组新增对照需要重新在同一台手机运行并导出自动诊断 TXT。
- 即使标准 Chrome GET 在当前手机成功，仍需另一台未登录百度的设备/不同 IP 实测，才可能宣称匿名分享行为通过。
- CDN URL 仍可能含临时签名，外部发布前检查隐私/服务限制。不能保证免认证、永久有效、解除限速。
- 完整 2.27 GiB 文件哈希校验仍未覆盖。

## 用户最短操作

更新 V1.8 → 打开 APP 的「我的网盘」 → 搜索视频 → 点击「获取最终下载直链（自动验证）」 → 截图四组 HTTP 结果；高级功能 →「导出自动诊断 TXT」。无需手动「开启日志」，无需自建服务器。
