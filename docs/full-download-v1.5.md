# PanLocal V1.5 安卓本地实际文件下载 — 首个实测候选

## 用户实测基础

用户使用 V1.4、同一个百度网盘开发者账号，对 2270.66 MiB 视频已确认：
- OAuth 通过，个人文件搜索结果正确
- filemetas 接口返回 dlink
- APP 内带 `access_token` + `User-Agent: pan.baidu.com` + `Range: bytes=0-0` 后，HTTP 302 → 206，content-type video/mp4，首字节实际读取成功

所以 **V1.4 只有验证，没有保存整文件的功能**，用户问“怎么下载”并不是操作不当。

## V1.5 新增

- 搜索结果的每个真实文件增加 **“下载到手机”**；打开 Android 原生 SAF 保存窗口，允许选择下载目录和文件名，无需访问全部存储权限。
- 新增 `BaiduDownloadService.java` Android `dataSync` 前台服务；大文件边下载边写入选定的 `content://` 文档，而不是全部载入手机内存。
- 服务从本人网盘的 `filemetas` 取得新 dlink，仅在内存中附加已授权 `access_token`，GET 使用 `User-Agent: pan.baidu.com` 和 `Range: bytes=offset-`。
- 仅允许 HTTPS 百度 PCS 下载域名与已验证的重定向；收到 206 时验证 `Content-Range` 起始偏移，否则停止，防止在恢复下载时写坏文件。全部使用 64 位 long 处理超过 2 GiB 的文件长度。
- APP 中显示已下载 MiB、总大小和比例；Android 通知栏显示下载进度，支持暂停、继续、停止。暂停期间服务和进程继续存在；续传时重新获取新 dlink 并从当前保存长度发起 Range。
- 网络异常有限重试；真正完整写入预期大小后才显示“下载完成”。
- 每次下载只处理一个文件。TXT 日志仅记录阶段、错误类型、下载完成的字节数，不记录 `access_token`、SecretKey、完整下载 URL、文件名。

## 安卓操作

1. 安装 V1.5 → 打开我的网盘；此前保留的授权在同签名更新后可自动恢复。
2. 搜索“传奇”，找到约 2270.66 MiB MP4。
3. 点击 **“下载到手机”** → 在 Android 文件选择器选择目录、确认文件名。
4. 等待“下载已启动”，在 APP 或手机通知栏查看进度。APP 前台页面提供暂停/继续；通知栏可以暂停、继续、停止。
5. 直到确认完成才打开手机文件管理器，在原保存目录查看视频。

## 限制及验收状态

- 【代码目标】前台服务可在 APP 界面切到后台后持续下载；实际是否被手机系统省电策略杀死，需真机验证。
- 【已实现但尚未实测】暂停/继续只保证**同一服务进程仍存活**的会话内有效。应用进程被杀、强制停止、系统重启后**不保证自动恢复**。部分文件可能保留在手机，切勿误认为已经下载完成。
- 【待测】实际 2.27 GiB 下载、视频可播放、大小匹配、MD5/哈希完整性和速度；仅验证整文件收到预期字节数不代表文件内容哈希已经通过。
- 【待测】某些 Android 文件提供程序可能不支持写入或 64 位 Seek；按系统提示选择下载目录并提供脱敏日志。
- 【待测】Android 13+ 可能要求通知权限；即使用户不允许通知，也可能在界面下载，但后台状态提示会受影响。
- 【非目标】免会员限速、破解百度服务端限制；只能在百度授予的权限内访问本人文件。
- 【部署】只修改用户的独立 GitHub 项目 `lgf921375/panlocal-android`，不访问新加坡服务器，不修改其它项目或服务。

更新前保存需要的 TXT 日志。GitHub Actions 调试签名可能变化，卸载旧版会清除 Android Keystore 中的开发者密钥和 OAuth 令牌。
